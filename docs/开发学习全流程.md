# 开发学习全流程

## 一、学习目标与总体结构

现状：已经通过 AI 协作开发积累了真实的产品、接口、数据保存、Git、部署和桌面应用经验；这些经验尚未系统连接成计算机科学知识体系。传统从编程语言教材第一章顺序复习的方式缺少实际问题与学习动力。另一个独立目标是理解 AI 模型本身及其前沿研究，而不止会调用模型。

学习目标分为两条主线：

- **A｜计算机科学与软件工程**：从能提出需求和使用 AI 开发，逐步达到能阅读代码、追踪执行过程、独立实现关键逻辑、定位错误、解释设计取舍并验证改动。
- **B｜人工智能原理与研究**：从模型的基本使用与能力认知，深入机器学习、深度学习、语言模型的训练和推理，逐步能够分析技术报告、评测和前沿论文。
- **C｜AI 应用工程（交叉模块）**：把 A 的应用系统、数据、测试能力与 B 的模型知识用于 RAG、工具调用、Agent、Harness 和实际工作流评估。

开发流程、Git、终端、调试、测试作为贯穿两条主线的能力。AI 前沿阅读从开始就进行，不必等待开发基础全部学完。

知识范围参照 [ACM/IEEE-CS/AAAI CS2023 知识领域](https://csed.acm.org/knowledge-areas/) 及 [CS2023 报告](https://csed.acm.org/wp-content/uploads/2025/11/CS2023-Report.htm)；这是面向个人开发与 AI 研究的选择性课程，不等同于完整计算机科学本科培养方案。计算机体系结构、编译原理、形式化证明、分布式系统、图形学等按基础和拓展两级安排，避免把兴趣驱动的学习变成所有专业必修课的堆叠。

### 知识依赖与推进方式

知识地图规定必须覆盖的原理，实际问题决定进入知识的方式；目录顺序用于索引，不等于逐章串行的硬性要求。两条主线并行，工程质量贯穿全程。

- A00 诊断后，从序流收支进入 A01.1—A01.2，再学 A04.2—A04.3 的交互和状态。A01.3—A01.5 随模块、校验、文件和运行环境补齐；A02 与 A03 交替推进。
- A04.1 网络概念可提前观察；A04.4—A04.6 的实现需 A01.3—A01.4 与 A03.3 异步基础。A05.1—A05.3 只需基本数据操作，事务与一致性再结合 A03.4。A06.1—A06.3 的小程序设计和 A07.1—A07.3 的基本工程习惯从第一节开始。
- A02.0 将离散数学嵌入算法正确性、递归与图；A03.1 将计算机体系结构嵌入运行、内存及性能，不要求先修完整离散数学或硬件课程。
- B00 → B01.0（Notebook 数据实验）→ B01.1—B01.3 与 B02 交替。回归需向量和梯度，分类补概率和交叉熵，B01.4—B01.5 随 B02.3、B03 深化。
- B03 先学前向传播、梯度和最小训练循环，再深化优化及泛化；完成小网络后进入 B04 字符模型、Tokenizer、Attention 与微型 GPT。B05/B06 可交替；B07 从 B00 起持续推进。
- C01 需 A01.4、A04.1/A04.4、B00；C02 需 A05.1/A05.2、B01.1、B04.2、C01；C03 需 C01、A01.3/A01.4、A04.4、A06.2 基础；C04 需 C02/C03、A07.1/A07.2、B02.4/B02.6、B06.4。
- 诊断已达标的节点可跳过教材与重复练习。仅认识名词或曾让 AI 实现过，不算通过。每次 30—60 分钟，复杂节点分次完成。

## 二、学习方式与实践边界

### 每个节点如何学习

1. **实际问题导入**：从项目现象或模型技术问题出发，自己提出可能的解释。GPT 可列出 3—5 个核心问题、指定资料及先修缺口，不先给出全部答案。
2. **系统理论**：读该节点的指定教材范围，弄懂定义、运行机制、关系、适用条件和典型错误；通过知识树确保不会只学习当前 Bug 所需的片段。
3. **最小独立实验**：用短程序、可视化、计算或小数据集验证原理。先预测结果，再运行；需要帮助时先让 AI 提示而非整段代写。
4. **真实项目联系**：追踪对应代码、数据和日志，判断已有实现的取舍。若要练习修改，使用独立副本、模拟数据、隔离测试环境或明确授权的分支；无需为了学习向正式项目添加无用功能。
5. **回顾与迁移**：合上材料解释原理，独立完成一个变化条件后的任务，记录证据。让 GPT 根据真实回答和实验结果找错，而不是仅凭自评标记完成。

每节保留三项：关键概念与关系、能解释的代码/计算/示意、一次实际验证结果。学迹记录位置、停点和下一步，Obsidian 保存有长期价值的理解与实验结论。序流安排实际学习时间。正式产品开发仍可使用 Vibe Coding，不要求每次开发都转为教学。

**掌握标准**：接触（能识别概念）→ 理解（能解释因果并追踪例子）→ 应用（能独立完成关键实验与验证）→ 迁移（能在新场景选择方案、定位问题）。核心节点至少达到应用，综合模块要求迁移；阅读型拓展节点可止于理解。已通过的内容不重复刷课，未通过的节点明确缺失的先修知识再回补。

### 独立能力训练：阅读 → 追踪 → 修改 → 实现 → 设计

| 级别 | 练习 | 最低证据 |
| --- | --- | --- |
| R1 Read（阅读） | 阅读少量实际代码，标出输入、输出和职责 | 不看 AI 解释，准确说明主要语句 |
| R2 Trace（追踪） | 给定输入，预测执行、变量、状态与异常 | 断点、日志、手算或运行结果核对预测 |
| R3 Modify（修改） | 改一条已有规则 | 自己修改关键代码，测试正常与边界情况 |
| R4 Implement（实现） | 给定接口或测试，实现小函数、组件或模型计算 | 从骨架补全核心逻辑，解释失败和修正 |
| R5 Design（设计） | 为新问题选择结构、接口、架构或实验方案 | 比较两种方案，用验证结果支持判断 |

A00 诊断起点；A01/A04 从 R1/R2 逐步到 R3/R4；A02/A03/A05 各至少完成一项 R4；A06/A07 综合任务达到 R5。B01—B04 从公式与代码追踪到独立实现；B05—B07、C 线侧重设计、对照、评价。当前能力不足时只增加一级训练，不要求一开始独立完成整个应用。

正常产品开发继续使用 Vibe Coding；学习实验由 AI 提供问题、代码位置、测试或最小骨架，自己先预测并完成关键部分。卡住时依次请求概念提示、伪代码、局部提示，最后才看完整答案。看过完整答案后换一个类似问题独立重做才算应用通过。查阅教材、API 文档允许；关键练习不能全由 AI 代写。

## 三、A｜计算机科学与软件工程

### A00｜入口诊断与工程工作流（不重复完整开发流程课程）

**先修**：现有开发经历。首选序流“每日收支详情”，必要时用学迹“归档学习方向”交叉验证。每项先独立尝试 10—20 分钟；诊断允许失败，失败决定学习起点，不要求新增功能。

- A00.1 画出问题→需求与验收→方案→实现→测试→发布与观察→修复/回滚；指出当前版本、未提交改动及线上版本。
- A00.2 在 AI 不代写的情况下，从入口追踪一个功能的调用、状态、保存、显示；解释哪些文件是必要修改。
- A00.3 独立写一个小计算或状态转换函数，给出正常、空和异常输入；用断点或日志定位一个故意制造的错误。
- A00.4 说明本地工作区、暂存区、提交、分支、远端、构建、部署的差别；在隔离仓库练习 diff、提交和恢复。

资料：[GitHub 开发流程](https://docs.github.com/en/get-started/start-your-journey/writing-and-storing-your-code)、[Pro Git 中文版](https://git-scm.com/book/zh/v2) 第 1—3 章、[Vercel 部署文档](https://vercel.com/docs/deployments)。已掌握部分跳过教学，只补不能解释或操作的部分。输出能力缺口清单：节点 ID｜任务｜R1—R5｜独立/提示/代写｜证据｜待补知识。不会读代码从 A01.1—A01.2 开始；能追踪但不能修改重点练 R3；能修改但不能实现进入 R4。已掌握的 Git/流程直接跳过。

### A03｜计算机系统、操作系统与并发

主资源：[3Blue1Brown 神经网络系列](https://www.3blue1brown.com/topics/neural-networks)、[Karpathy Neural Networks: Zero to Hero](https://karpathy.ai/zero-to-hero.html) 的 micrograd、makemore 前几讲、[PyTorch Learn the Basics](https://docs.pytorch.org/tutorials/beginner/basics/)、[动手学深度学习](https://zh.d2l.ai/) 第 3 章线性神经网络、4.1—4.8 多层感知机与反向传播、5.1—5.5 深度学习计算、11.3—11.5/11.10 优化；B03.5 选第 6、8 章。PyTorch Learn the Basics 按 Quickstart → Tensors → Datasets & DataLoaders → Build Model → Autograd → Optimization → Save & Load Model；训练小网络前先通读 Quickstart，再按概念顺序深化。

**阶段验收**：独立完成一次小网络训练，手算并验证局部梯度，解释训练循环、优化器、过拟合和误差来源。若梯度只会调用库而不理解，先回 B01.3。

### B04｜语言模型与 Transformer

**先修**：B03.1—B03.4、B01.4；B03.5 先理解序列建模。**问题**：长上下文为什么增加计算成本，MoE 总参数与激活参数为何不同？N3 字符模型理解概率预测，N4 实现 Attention 与微型 GPT，再用模型架构报告检验理解。

| 节点 | 知识 | 实验与验收 |
| --- | --- | --- |
| B04.1 | 语言建模、条件概率、n-gram、next-token prediction、困惑度 | 实现字符级 bigram，比较上下文变化及损失 |
| B04.2 | Tokenizer、字符/子词、BPE、词表、Embedding | 对比不同文本的 token 数量，观察向量形状；理解 token 与字符、词的差异 |
| B04.3 | Self-Attention、Q/K/V、缩放点积、Mask、多头注意力 | 手算小矩阵的注意力权重，在代码中复现因果 mask，解释各矩阵的作用 |
| B04.4 | Transformer Block、位置编码、残差、归一化、MLP、Decoder-only | 画一个 Block 的数据流与维度变化；用微型模型验证不同上下文的预测 |
| B04.5 | 参数规模、上下文长度、Dense/MoE、路由与负载均衡 | 比较概念性 Dense/MoE 的总参数与每次激活参数；理解容量和计算的区别及通信限制 |
| B04.6 | 从原始模型到文本生成，训练模式与推理模式 | 跟随小型 GPT 实验，能解释训练目标和自回归生成，并独立修改一个明确的组件或参数 |

主资源：[Karpathy Zero to Hero](https://karpathy.ai/zero-to-hero.html) 的 makemore、Let's build GPT；[Hugging Face LLM Course](https://huggingface.co/learn/llm-course/en/chapter1/1) 的 Transformer、模型与 Tokenizer（第 1、2、6 章）；《动手学深度学习》8.1—8.3、10.3、10.5—10.7 为语言模型和注意力中文理论；[3Blue1Brown Attention](https://www.3blue1brown.com/lessons/attention/)；原始论文 [Attention Is All You Need](https://arxiv.org/abs/1706.03762) 在理解基本机制后选读。

**阶段验收**：能画出文本→token→Embedding→Transformer→logits→下一 token 的计算链；完成小型注意力/语言模型实验，并解释训练和生成的差别。

### B05｜模型训练、后训练与能力形成

**先修**：B03、B04。**问题**：推理模型的能力变化可能来自数据、奖励、搜索或推理时计算中的哪些因素？N5 延续微型 GPT 或公开小模型实验，控制数据与评测条件，再对照真实模型技术报告。

- B05.1 预训练目标、数据清理和去重、训练/评估污染、数据混合、规模与计算预算。阅读技术报告中的数据和训练条件，区别证据与推断。
- B05.2 监督微调（SFT）、指令数据、参数高效微调（如 LoRA）、灾难性遗忘及对照实验。用小模型或公开 Notebook 观察微调前后，记录同一测试集的变化。
- B05.3 偏好数据、奖励模型、强化学习（RL）的状态/行动/奖励/策略与策略优化基础；理解 RLHF、DPO 与强化学习式后训练的不同目标和条件。
- B05.4 推理模型、可验证奖励、过程与结果监督、训练时计算和推理时计算。分析一篇推理模型技术报告，区分实际披露的训练方法和猜测。
- B05.5 训练系统基础：GPU、显存、混合精度、批量、梯度累积、数据/模型并行的动机。小实验可使用 CPU 或免费 Notebook，不要求训练商业规模模型。

主资源：[Stanford CS336: Language Modeling from Scratch](https://cs336.stanford.edu/) 的数据、架构、训练及后训练部分（按课程当期目录定位）；[Hugging Face LLM Course](https://huggingface.co/learn/llm-course/en/chapter1/1) 的模型微调、数据集与高阶 LLM 主题；[Hugging Face Deep RL Course](https://huggingface.co/learn/deep-rl-course/unit0/introduction) 基础单元。

**阶段验收**：解释预训练、SFT、偏好优化和 RL 在目标、数据、更新方式上的区别，独立做一项小规模训练/微调对照实验或可复现的玩具奖励实验。完整 RL 推导、分布式训练及论文复现进入进阶阶段。

**CS336 进阶门槛**：Stanford CS336（2026）官方要求熟练 Python、PyTorch、深度学习、系统优化与大学数学。第一轮只选相关讲义和 Assignment 1 的小模型思想；完整 Assignment 1、GPU/Triton 与分布式训练留到能独立训练小模型、理解内存层级和完成性能测量后。

### B06｜推理系统、模型效率与评测

**先修**：B04；性能结合 A03/A07，后训练评测结合 B05。**问题**：长上下文、推理 token 和 Harness 为何影响速度、成本及任务成功率？分别测模型生成与端到端任务，区分模型计算、工具耗时、网络等待。

- B06.1 自回归推理、logits、Temperature、Top-k/Top-p、停止条件。固定输入比较采样行为，记录随机性。
- B06.2 Prefill、Decode、KV cache、上下文长度、批处理、延迟/吞吐、显存。测量小模型或公开 API 的首 token 延迟与生成速度，明确网络、服务端排队等影响。
- B06.3 量化、蒸馏、稀疏与 MoE 推理、投机解码、推理时计算的基本动机；能比较精度、成本与速度的权衡。
- B06.4 评测数据集、指标、基线、任务分布、置信与不确定性、数据污染、模型裁判偏差。对比官方报告与独立评测，关注设置是否相同。
- B06.5 实际模型/Agent 评估：固定任务、环境、资料、时间和工具，重复试验并记录成功率、耗时、成本、返工、失败类型。区分模型能力与 Harness 的贡献。

主资源：Stanford CS336 的 Inference/Evaluation 相关讲次；Hugging Face 模型与生成相关文档；[SWE-bench](https://www.swebench.com/)、[METR](https://metr.org/time-horizons/) 的方法及限制。

**阶段验收**：独立解释影响模型推理速度和成本的因素；对一个真实 AI 工作流实施小型、可重复的对比评测，并基于证据解释结果。
