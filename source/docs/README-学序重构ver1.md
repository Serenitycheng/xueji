# 学序 0.5.0 修改说明

这次修改围绕一件事：隔了一段时间重新打开学序时，能够找到上次学到哪里、卡在哪里，以及接下来可以做什么。

本轮依据《学序功能重构说明ver1》完成 P0 基础学习流程，继续使用现有学序项目、账户、云端存储和资料体系。新流程可以手动使用，无需先配置 AI、上传材料或制定完整路线。

| 入口 | 用途 |
| --- | --- |

## 新增与调整的功能

### 1. 手动建立学习方向与单元

- 只填写方向名称即可创建，支持课程、技能、阅读与探索三种类型。
- 阶段目标、材料和完整路线可以后续补充；先建立一个当前单元也能开始。
- 单元支持添加、编辑、排序和设置为当前内容。
- 同名单元有各自的身份，改名或调整顺序不会合并单元或丢失已有记录关联。
- 新账户从空方向列表开始，不生成演示进度。

### 2. 保存停点、卡点和下一步

进入方向后，可以查看当前内容、最近实际结果、尚未解决的卡点和已确认的下一步。

“记录与接续”用于结束一次学习：填写实际结果、状态判断或下一步中的必要内容即可，位置、卡点和依据可按需展开填写。完全空白的记录不会保存。

一个方向保留一个当前下一步：

- 没有填写新的下一步时，保留原有内容，并提示本次尚未更新。
- 明确填写新行动时，用它接续后续学习。
- 也可以主动清空下一步，暂时不设置。
- 有已确认行动时，规则建议不会替换它。尚未设置行动时，可查看规则建议及依据，确认后才成为正式下一步。

最近一次记录支持修正，并保留原记录和修正关系；已有后续记录或已经切换单元时，使用新记录补充说明。

### 3. 分开记录接触状态与掌握判断

接触状态表示是否接触过内容；掌握判断表示当前对自己能力的判断。看过、投入时间或完成旧任务，都不会自动变成“能够独立完成”。

用户可以暂不判断掌握情况，也可以明确填写判断及依据来源。自评会保留其来源，不显示成已经通过测试的认证结果。

阅读与探索方向可以只记录位置、问题和下一步，记录表单不强制填写掌握判断。

### 4. 暂停、恢复与历史保留

方向可以暂停、恢复、确认完成或归档。暂停后退出活跃学习建议；恢复后保留原有路线、记录、材料和下一步，不生成中断期间的补学欠账。

### 5. 关联材料与笔记

方向和单元可以关联已有附件、网页、本地文件路径、教材位置或笔记入口。

- 原开发学习方案 PDF 保留原文件，继续通过登录保护的入口访问。
- 笔记引用支持网页地址和 Obsidian 打开链接；库名和文件位置进行编码处理。
- 原文件与笔记正文留在原位置，不自动扫描笔记库，也不默认把原件全文发送给 AI。
- 本地路径和笔记入口提供复制退路。私有附件访问失败时显示具体提示。

Obsidian 链接的编码和参数约束已经测试，用户真实笔记库中的实际打开效果尚未验证。

### 6. 复制学习行动到序流

“复制学习行动”生成包含标题、具体动作、开始位置、结束条件、学习方向链接及相关入口的摘要。复制后可以自行粘贴到序流安排执行。

当前实现只复制摘要，不自动创建序流任务，也不回传序流任务的完成状态。

### 7. 保存、草稿与冲突处理

- 学习记录表单支持当前浏览器的本机草稿，未提交内容可以在刷新后恢复。
- 学习记录和下一步共同保存，失败不会只写入其中一部分。
- 同一次提交通过稳定编号和保存回执处理重试，避免重复产生记录。
- 遇到云端已有更新时，保留本机输入并显示冲突比较，不静默覆盖较新的内容。
- 已打开页面断网时，可保留待提交操作；恢复网络后继续处理。
- 界面区分本机草稿、保存中、已保存和失败状态；本机草稿不代表已经写入云端。

目前还不是可以完全离线启动的 PWA。学习记录以外的其他表单主要在当前页面保留输入，离开前需要先保存。

## 使用示例：从开发学习开始

以下为操作示例，不会自动写入账户。

1. 打开“学习方向”，新建“开发学习”；已有该方向时直接进入。
2. 设置阶段目标，例如“能够读懂并修改一个小型项目”。
3. 添加当前单元，例如“Python 条件判断”，选择为当前内容。
4. 保存下一步，例如“独立写一个根据输入分数判断结果的小程序”，补充开始位置和结束条件。
5. 实际学习或做项目后，打开“记录与接续”，记录完成了什么、卡在哪里；没有检验能力时可以保持未判断。
6. 保存下一步后离开。再次进入“继续学习”，从保存的位置接着做。
7. 暂时不推进时暂停方向；需要安排执行时间时复制学习行动到序流。

## 原有数据与功能如何处理

| 原有内容 | 本次处理 |
| --- | --- |
| 个人密码登录、账户与云端存储 | 继续使用现有实现 |
| 旧学习方向 | 保留原 ID、名称、目标和暂停状态，兼容读取为新方向 |
| 已选定的旧路线 | 将阶段内容兼容读取为稳定 ID 的单元；没有可靠起点时不自动指定当前单元或下一步 |
| 任务、课表、考试信息、时长、分数、旧计划和日志 | 保留原字段，提供只读历史和导出入口，不推断成掌握状态 |
| 已有附件与开发方案 PDF | 保留原文件和引用标识，继续使用原私有访问方式 |
| 内容历史、版本与保存回执 | 继续使用，学习修改也纳入相同保护 |
| DeepSeek 连接、模型和预算设置 | 保留配置；本轮基础流程不依赖 AI，调整预算不再重排旧任务 |

新结构以 `learning` 字段加入现有学习状态，数据外壳版本仍为 `1`，写入协议升级为 `5`。兼容转换可重复执行，不重复创建方向或单元；旧记录中的未知字段继续保留。

JSON 导出包括学习状态、历史兼容字段与资料索引，不包含私有附件本体、资料全文、密码或 API Key。开工前的源码备份包含随仓库保存的开发方案 PDF，但不等于生产数据库和全部附件的备份。

## 发布兼容说明

新增迁移 `0005_learning_workspace.sql` 更新数据库写入保护，要求使用协议 `5`，没有删除表或清空学习数据。

现有 Vercel 发布脚本会先完成应用构建，再在生产环境执行待应用的前向迁移；预览和本地构建跳过数据库迁移。旧页面需要刷新，本机资料处理器也需要使用兼容版本。

本文未单独读取生产数据库验证实际协议。生产数据备份与原件核对应独立留存证据；发生新写入后，不能直接用旧数据库备份覆盖新记录。
